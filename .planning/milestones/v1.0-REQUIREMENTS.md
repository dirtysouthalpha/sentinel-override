# Requirements: MediaSentinel v1.0 (ARCHIVED)

**Defined:** 2026-05-02
**Archived:** 2026-05-04
**Status:** ALL REQUIREMENTS COMPLETE
**Core Value:** 24/7 autonomous uptime for the entire media stack with zero-tolerance VPN enforcement for torrent downloads

## v1 Requirements

### Health Monitoring

- [x] **MON-01**: System polls HTTP health endpoints for all 8 services (Jellyfin, Jellyseerr, Radarr, Sonarr, Shoko, Prowlarr, Cloudflare Tunnels, qBittorrent) with configurable intervals — Phase 2
- [x] **MON-02**: Each health check returns standardized status (healthy/degraded/unhealthy) with response time, version, and dependency status — Phase 2
- [x] **MON-03**: Critical services (Jellyfin, VPN) polled every 15 seconds; non-critical services every 30 seconds — Phase 2
- [x] **MON-04**: Health check failures trigger recovery after configurable consecutive failure threshold (default: 3) — Phase 2

### VPN Monitoring

- [x] **VPN-01**: VPNGuard detects VPN interface via Windows adapter enumeration (psutil), not Linux interface names — Phase 2
- [x] **VPN-02**: Verifies VPN connection by checking adapter status, assigned IP, and external IP match — Phase 2
- [x] **VPN-03**: Performs DNS leak test via dnspython to verify DNS queries route through VPN, not ISP — Phase 2
- [x] **VPN-04**: Performs IP leak test to verify external IP belongs to VPN endpoint, not real IP — Phase 2
- [x] **VPN-05**: Measures VPN connection latency and reports degradation — Phase 2
- [x] **VPN-06**: Polls VPN status every 10 seconds with state transitions logged — Phase 2

### Recovery Engine

- [x] **REC-01**: Implements 7-level escalation hierarchy: self-heal, soft restart, dependency recovery, stack reset, VPN recovery, network recovery, operator escalation — Phase 3
- [x] **REC-02**: Each escalation level has defined triggers, timeouts, retry counts, and automatic escalation to next level — Phase 3
- [x] **REC-03**: Dependency-ordered recovery follows tree: VPN -> Tunnels -> qBittorrent -> Jellyfin -> Prowlarr -> Radarr/Sonarr -> Jellyseerr -> Shoko — Phase 3
- [x] **REC-04**: State snapshot captured as JSON before every Level 2+ recovery action — Phase 3
- [x] **REC-05**: Circuit breaker prevents more than 3 recovery attempts in 10 minutes per service — Phase 3
- [x] **REC-06**: Recovery actions use Docker SDK for containers, subprocess for host services (cloudflared, VPN daemon) — Phase 3

### qBittorrent Integration

- [x] **QBT-01**: WebAPI client connects to qBittorrent via qbittorrent-api with proactive session re-authentication — Phase 4
- [x] **QBT-02**: VPN-gated download state machine: INIT -> VPN_VERIFIED -> VPN_DOWN -> VPN_RECOVERING with safe-default (fail closed) — Phase 4
- [x] **QBT-03**: Immediately pauses all downloads when VPN disconnects or fails leak tests — Phase 4
- [x] **QBT-04**: Resumes downloads only after VPN is verified connected AND DNS/IP leak tests pass — Phase 4
- [x] **QBT-05**: Version-aware API wrapper handles qBittorrent v4 (pause/resume) and v5 (stop/start) endpoint differences — Phase 4
- [x] **QBT-06**: 4 speed profiles (10/50/100/100+ Mbps) with 85% bandwidth utilization and configurable connection limits — Phase 4
- [x] **QBT-07**: Verifies qBittorrent network interface binding to VPN adapter on startup and periodically — Phase 4

### Cloudflare Tunnel Monitoring

- [x] **TUN-01**: TunnelGuard monitors tunnel health via round-trip URL verification (not /ready endpoint alone) — Phase 2
- [x] **TUN-02**: Verifies tunnel status via Cloudflare API v4 — Phase 2
- [x] **TUN-03**: Restarts cloudflared daemon on tunnel failure and verifies reconnection within 30 seconds — Phase 2
- [x] **TUN-04**: DNS validation confirms CNAME records point to active tunnel — Phase 2

### Dashboard

- [x] **TUI-01**: Textual TUI dashboard displays real-time status for all services, VPN state, and download speeds — Phase 5
- [x] **TUI-02**: Dashboard auto-refreshes via Textual's set_interval with no blocking operations — Phase 5
- [x] **TUI-03**: Displays recovery event log with timestamps, actions taken, and outcomes — Phase 5
- [x] **TUI-04**: Shows VPN status panel with connection state, server location, latency, and leak test results — Phase 5

### Alerting

- [x] **ALT-01**: 4 severity levels: INFO (log), WARNING (log + notification), CRITICAL (log + notification + recovery), EMERGENCY (all channels + human escalation) — Phase 6
- [x] **ALT-02**: Multi-channel notifications: email (SMTP), webhook (Discord/Slack/Gotify), structured log output — Phase 6
- [x] **ALT-03**: Alert includes diagnostic context: service state, recent recovery actions, resource usage, VPN status — Phase 6
- [x] **ALT-04**: Configurable escalation rules per severity level with recipient routing — Phase 6

### Metrics and Observability

- [x] **MET-01**: MetricsCollector agent tracks per-service uptime %, MTTR, failure frequency, response time trends — Phase 6
- [x] **MET-02**: Tracks VPN connection stability: uptime, leak test results over time, latency trends — Phase 6
- [x] **MET-03**: Tracks qBittorrent download throughput over time and speed profile effectiveness — Phase 6
- [x] **MET-04**: Stores all metrics in SQLite with WAL mode for concurrent access — Phase 1
- [x] **MET-05**: Detects bandwidth throttling when sustained throughput drops below 50% of configured speed profile — Phase 6

### Configuration and Logging

- [x] **CFG-01**: YAML configuration file defines service URLs, API keys, check intervals, recovery thresholds, alert recipients — Phase 1
- [x] **CFG-02**: Pydantic-validated config models with clear error messages on misconfiguration — Phase 1
- [x] **CFG-03**: Structured JSON logging via loguru with timestamp, severity, component, action, result fields — Phase 1
- [x] **CFG-04**: All health checks logged to /var/log/mediasentinel/health.log, recoveries to recovery.log — Phase 1
- [x] **CFG-05**: CLI entry point via click with subcommands: start, status, logs, recover, config — Phase 1

### Deployment

- [x] **DEP-01**: Docker Compose configuration with HEALTHCHECK definitions for all containerized services — Phase 7
- [x] **DEP-02**: MediaSentinel runs as persistent process (Windows service or Docker container) with auto-restart — Phase 7
- [x] **DEP-03**: Graceful shutdown preserves state: pauses downloads, saves snapshot, flushes logs — Phase 7
- [x] **DEP-04**: Health check wrapper scripts in /opt/healthchecks/ for each service returning standardized JSON — Phase 2
