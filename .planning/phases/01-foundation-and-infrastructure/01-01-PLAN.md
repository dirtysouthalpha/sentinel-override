<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| config.yaml file -> Pydantic models | Untrusted input from filesystem; user-controlled YAML content crosses into application config |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-01-01 | Tampering | config/loader.py | mitigate | Pydantic extra='forbid' rejects unknown keys, field validators enforce type/range constraints, no eval/exec on YAML content (safe_load only) |
| T-01-02 | Information Disclosure | config.yaml | accept | Config file may contain service URLs and API key references; no secrets stored in values (env var names only per AlertConfig.smtp_password_env). Single-operator machine, no multi-user risk. |
| T-01-03 | Tampering | config.yaml paths | mitigate | Path traversal not possible in this phase -- paths are read from config for later use, not used to write/delete files. Logging/DB path validation deferred to their respective modules. |
</threat_model>
