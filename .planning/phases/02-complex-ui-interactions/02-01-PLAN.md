**content/shadow-dom.js** -- Replace stubs with full implementations:

1. `queryDeep(root, selector)` -- recursively search piercing open shadow roots using TreeWalker. Fast path: try querySelectorAll first, then walk elements checking shadowRoot. Returns Element[].
2. `queryDeepFirst(root, selector)` -- returns first match only (more efficient for single element lookups).
3. `getShadowRoot(el)` -- returns el.shadowRoot for open, or check WeakMap of intercepted closed roots (from shadow-intercept.js).
4. `walkShadowTree(root, callback)` -- walks entire tree including shadow roots, calling callback for each element.
5. `isInShadowDOM(el)` -- returns true if element's root node has a host (i.e., is inside shadow DOM).
6. `_capturedShadowRoots` WeakMap for closed shadow root interception (populated by shadow-intercept.js).
All functions stored on `window.__sentinelUtils.shadow`.

**content/dom-utils.js changes:**

1. **Update scanDocument**: After scanning visible elements in the light DOM, call `walkShadowTree` from shadow-dom.js to also find interactive elements inside shadow roots. Add `inShadowDOM: isInShadowDOM(el)` property to each scanned element's metadata.

2. **Update findElementBySelector**: After the existing querySelector attempt, also try `queryDeepFirst` from shadow-dom.js as a fallback. This makes the agent shadow-DOM-aware transparently.

<task type="auto">
  <name>Task 2: Implement dropdown and nested menu interaction utilities</name>
  <files>content/dropdown-utils.js</files>
  <action>
Create content/dropdown-utils.js with functions for detecting, opening, and interacting with custom dropdown components (Angular Material, React Select, Ant Design, Ext JS) and nested hover menus.

**Functions to implement:**

1. `openDropdown(doc, triggerEl)` -- Opens a custom dropdown by clicking the trigger element, then waits for option elements to appear via polling (every 100ms, up to 3s timeout). Returns the option elements array, or null if opening failed. Scrolls trigger into view before clicking. Uses full mouse sequence (mousedown/mouseup/click/mouseout) consistent with existing click pattern.

2. `findDropdownOptions(doc, triggerEl)` -- Finds dropdown option elements after a dropdown is opened. Checks multiple patterns in order:
   - ARIA pattern: `[role="option"]`, `[role="listbox"] [role="option"]`
   - Common containers: `.dropdown-menu`, `.select-options`, `.menu`, `[role="menu"]`, `.autocomplete-list`
   - Siblings/children of trigger: `li`, `[role="option"]`, `.option` near the trigger
   - Also search inside shadow roots via queryDeep
   - Returns array of visible option elements, filtered by isVisible

3. `selectDropdownOption(doc, optionEl, value)` -- Selects a specific option from an open dropdown. Strategies:
   - If option text matches value: click it (with full mouse sequence)
   - If options don't match: try typing in a search/filter input within the dropdown container first
   - Scroll option into view before clicking
   - For large lists (50+ options): look for a search input within the dropdown container, type the value, then wait for filtered results and click the first match

4. `traverseNestedMenu(doc, menuPath)` -- Traverses a nested hover/click menu structure. menuPath is an array of strings like ["Settings", "Security", "Firewall Rules"]. For each level:
   - Find the menu item matching the text
   - Hover over it (dispatch mouseover + mouseenter events)
   - Wait 300ms for submenu to appear (check for visible child menu items)
   - Move to next level
   - Final item: click it (full mouse sequence)
   - Returns the clicked element or null if any level failed
   - Falls back from hover to click if hover doesn't reveal submenu within 500ms

5. `isCustomDropdown(el)` -- Heuristic to detect if an element is a custom dropdown trigger (not a native `<select>`). Checks:
   - Has ARIA role="combobox" or role="button" with aria-haspopup
   - Has class containing "dropdown", "select", "picker", "combobox"
   - Is a button/div near elements with role="listbox" or role="option"
   - Has a child or sibling with class "dropdown-menu" or "select-options"

6. `dismissDropdown(doc)` -- Closes any open dropdown by pressing Escape key or clicking outside. Returns true if a dropdown was visibly open (check for visible dropdown containers).

**Integration with existing commands:**
This task creates the utility module only. Wiring into the message handler happens in Task 3.

**Key design decisions (from CONTEXT.md):**
- Use DOM polling (not MutationObserver) for dropdown open detection -- simpler and reliable for enterprise UIs
- For large option lists: try search/filter input first, then scan visible options
- On selection failure: return null so the caller can retry with alternate strategy
- Use composed: true on all events for shadow DOM compatibility
