<objective>
Implement structured investigation report generation that automatically produces a copy-paste-ready markdown report after the agent completes a task.

Purpose: Users need documentation of what the agent did for ticket documentation and audit trails. The current finish handler only produces a plain text summary with extracted data. This plan adds a dedicated LLM call after task completion that generates a structured report with Goal, Steps Taken, Key Findings, Evidence, and Conclusions sections.

Output: A new `background/report-generator.js` module, modifications to the agent-engine finish handler to capture data and trigger report generation, and popup UI changes to display report cards and a report modal with export options.
</objective>

1. **`generateReport(executionData, CONFIG)`** -- async function that:
   - Accepts an object with: `{ goal, history, agentMemory, agentPlan, stepCount, apiCallCount, tabContexts }`
   - Builds a report prompt asking the LLM to produce a structured markdown report with these fixed sections:
     - **Goal** -- the original user goal
     - **Steps Taken** -- numbered list of key actions (NOT every single step -- the LLM should condense routine actions and highlight important ones)
     - **Key Findings** -- goal-relevant observations and discoveries (the LLM decides what counts as a finding vs routine)
     - **Evidence** -- references to extracted data from agentMemory (e.g., "IP 10.0.0.5 found in blocked connections log")
     - **Conclusions** -- summary of outcomes and any recommended next steps
   - Uses `callLLMWithRetry` from llm-client.js to make the report generation call (reuse existing retry logic for reliability -- do NOT duplicate fetch logic)
   - For the callLLMWithRetry call: construct a prompt that includes the goal, a condensed history (step number + action type + result, not full element lists), the agentMemory contents, the agentPlan if it exists, and a note about which steps have associated screenshots (from tabContexts -- do NOT embed the actual base64 images, just reference them by step number and tab label)
   - Parses the LLM response as markdown text (not JSON -- the report is free-form markdown)
   - Returns an object: `{ summary: string, fullReport: string, goal: string, timestamp: string }` where `summary` is the first paragraph or first 300 chars of the full report

2. **Modify agent-engine.js finish handler (lines 368-388):**
   - BEFORE the `break` statement (line 388), capture the execution data needed for the report:
     ```javascript
     const reportData = {
       goal,
       history: history.slice(),       // clone before it gets cleared
       agentMemory: { ...agentMemory }, // clone
       agentPlan: agentPlan ? agentPlan.slice() : null,
       stepCount,
       apiCallCount,
       tabContexts: getAllTabContexts().map(tc => ({ label: tc.label, url: tc.url, hasScreenshot: !!tc.snapshot }))
     };
     ```
   - After sending `agent_finished` message (line 386), also send a `report_data_ready` message to the popup so the popup can show a "Generating report..." indicator
   - Import `generateReport` from `./report-generator.js`
   - Call `generateReport(reportData, CONFIG)` AFTER the finish handler breaks out of the loop (after line 684 cleanup), NOT inside the loop. This means the report generation is async and non-blocking. Use `.then()` to handle the result and send a `report_generated` message to the popup
   - CRITICAL: The report data is captured BEFORE `history` is cleared at line 684. The `reportData` object is a snapshot that survives the clear

3. **Add report message types to message-protocol.js:**
   - Add a `sendReportUpdate` function that sends `{ action: 'report_update', status: 'generating' | 'ready' | 'error', report: object | null, error: string | null }`
   - Follow the existing pattern of fire-and-forget `.catch(() => {})` messaging

4. **Register report-generator.js in background/index.js:**
   - Add the import at the top alongside the other module imports (index.js is the service worker entry point that imports all background modules)
