# Phase 4: Reports & Multi-Provider LLM - Context

**Gathered:** 2026-05-04
**Status:** Ready for planning

<domain>
## Phase Boundary

Two independent capabilities: (1) structured investigation report generation after task completion, and (2) multi-provider LLM support with UI settings for switching between Claude and OpenAI. Reports summarize what the agent did; provider switching lets users choose their LLM backend. These are independent value-adds that can be planned and executed in either order.

</domain>

<decisions>
## Implementation Decisions

### Report structure & content
- Fixed base sections (Goal, Steps Taken, Key Findings, Evidence, Conclusions) with adaptive subsections generated by the LLM based on task type (e.g., "Firewall Rules Changed", "Users Affected")
- The LLM decides what counts as a "finding" vs a routine step — findings are goal-relevant observations, not every action
- Evidence (screenshots, data) is referenced by step number in the report text; the popup displays screenshots alongside the report (not embedded inline)
- Detail level: summary-focused by default with a "Show full details" toggle for the complete step-by-step log

### Report delivery & formatting
- Auto-generate a brief summary when the agent completes a task; user can click to expand into full report
- Report appears as an inline card in the chat feed with a button that opens a full-screen/modal report view
- Export options: copy markdown to clipboard, download as .md file, copy as plain text — all three available
- Report updates if the user gives follow-up commands after the initial task completes (accumulates across related tasks)

### LLM provider switching UX
- Dedicated "Providers" section in the settings modal (not in the chat header)
- Per-provider configurable settings: API key, model, custom endpoint URL, advanced params (max tokens, temperature)
- Provider switch takes effect immediately on the next agent action (mid-task switching allowed)
- Auto-validate provider settings on save with clear error messages if credentials/endpoint are bad

### Provider abstraction & behavior
- Vision supported on both Claude and OpenAI — agent screenshots work identically across providers
- Shared base system prompt with provider-specific tweaks (formatting instructions, capability notes)
- On provider failure: retry with exponential backoff, then show error with manual switch option
- Mid-task provider switch: keep conversation history and prepend a context bridge summary to the new provider

### Claude's Discretion
- Exact prompt format for report generation (what instructions the LLM gets to produce the report)
- Retry count and backoff timing for provider failures
- Context bridge message format when switching providers mid-task
- How adaptive subsections are named and structured in the report
- Report modal layout and styling
- Provider card layout in settings

</decisions>
