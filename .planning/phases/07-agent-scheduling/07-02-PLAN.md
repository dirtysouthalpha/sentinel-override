**Module structure:**
```javascript
// popup-modules/scheduler-ui.js
// Schedule management UI: list, create, enable/disable, delete, run history.
// Communicates with background via chrome.runtime.sendMessage (schedule_* actions).

const getState = () => window.__popupState;
```

**Functions to implement:**

1. `showSchedulesPanel()` -- exported globally via `window.showSchedulesPanel = showSchedulesPanel`:
   - Hide chat-container, templates-panel
   - Show schedules-panel with `display:flex`
   - Load templates list (for create form dropdown)
   - Load and render schedules
   - Send `schedule_clear_badge` message to clear notification badge
   - Start a refresh interval (every 30 seconds) to update countdown timers -- store interval ID and clear on panel hide

2. `hideSchedulesPanel()` -- exported globally:
   - Hide schedules-panel
   - Show chat-container
   - Clear refresh interval
   - Also hide templates-panel (mutual exclusion)

3. `loadAndRenderSchedules()` -- async:
   - Send `schedule_list` message
   - Render schedule cards into `#schedule-list`
   - If no schedules, show `.schedule-empty` message "No schedules yet. Click + New Schedule to create one."
   - For each schedule, render a card with:
     - Name (schedule-card-name)
     - Goal preview (truncated to 80 chars) or template name
     - Recurrence info: "Once" or "Daily at HH:MM" or "Weekly on Mon, Wed at HH:MM" or "Every N minutes"
     - Next run: show as countdown "Runs in 2h 15m" or as absolute date if > 24h away, or "Next run: May 12, 2026 9:00 AM"
     - Last run status badge (success/failure/skipped/pending) with color coding
     - Enable/disable toggle (checkbox styled as toggle-switch, or simple checkbox)
     - Action buttons: View History, Delete (with confirm())
   - Disabled schedules get `.disabled` class (dimmed)

4. `renderScheduleCard(schedule)` -- helper:
   - Returns HTML string for a single schedule card
   - Use `data-action` attributes on buttons for event delegation
   - Use inline time formatting (same relativeTime pattern as templates.js)
   - Countdown calculation: `nextRunAt - Date.now()` converted to h/m/s

5. `openCreateScheduleModal()`:
   - Show `#schedule-modal` with `.show` class
   - Set modal title to "New Schedule"
   - Send `template_list` to populate `#sch-template-id` dropdown
   - Reset all form fields to defaults
   - For `#sch-run-at`, set min to current datetime

6. `openCreateScheduleModalForTemplate(templateId, templateName)`:
   - Same as above but pre-select the template in the dropdown
   - Pre-fill name with template name + " Schedule"
   - Exported globally for potential "Schedule this template" button from templates panel

7. `handleSaveSchedule()`:
   - Gather form data:
     - name from `#sch-name`
     - source type from `#sch-source-type`
     - templateId from `#sch-template-id` (if template)
     - goal from `#sch-goal` (if freeform)
     - params from template param inputs (if template has params)
     - type from `#sch-type` (once/recurring)
     - For once: runAt from `#sch-run-at` (convert datetime-local to timestamp)
     - For recurring: interval, daysOfWeek (from checkboxes), time (from `#sch-time`), periodInMinutes (from `#sch-period` for custom)
   - Validate: name required, template or goal required, date/time required
   - Send `schedule_create` message with the schedule data object
   - Close modal
   - Reload and render schedules
   - Show success toast

8. `handleToggleSchedule(scheduleId, enabled)`:
   - Send `schedule_toggle` message
   - Reload and render schedules

9. `handleDeleteSchedule(scheduleId, name)`:
   - `confirm('Delete schedule "${name}"? This cannot be undone.')`
   - If confirmed, send `schedule_delete` message
   - Reload and render schedules

10. `showRunHistory(scheduleId, scheduleName)`:
    - Send `schedule_results` message with `{ id: scheduleId }`
    - Populate `#schedule-history-list` with result items
    - Each item shows: timestamp, status badge (success/failure), duration (completedAt - startedAt)
    - If result has report, show a "View Report" button that opens the report modal with the report content
    - Show modal with `.show` class

11. `closeScheduleModal()`:
    - Hide `#schedule-modal` by removing `.show` class

12. `closeHistoryModal()`:
    - Hide `#schedule-history-modal` by removing `.show` class

13. **Event delegation** on `#schedules-panel` for button clicks:
    - Listen for clicks on `[data-action="toggle"]`, `[data-action="delete"]`, `[data-action="history"]`
    - Extract scheduleId from `data-id` attribute
    - Route to appropriate handler

14. **Event listeners** for modal form interactions:
    - `#sch-source-type` change: toggle between template-field and goal-field visibility
    - `#sch-type` change: toggle between once-fields and recurring-fields visibility
    - `#sch-interval` change: show/hide weekly-days and custom-interval fields
    - `#sch-template-id` change: if template has params, render param input rows in `#sch-template-params` (same pattern as templates.js run modal)

15. **Helper: `formatCountdown(timestamp)`**:
    - If timestamp is null, return "Not scheduled"
    - If in the past, return "Overdue"
    - If < 1 hour: "Xm away"
    - If < 24 hours: "Xh Ym away"
    - If < 7 days: "Xd Xh away"
    - Else: formatted date string

16. **Helper: `escapeHtml(text)`**:
    - Duplicate locally (same pattern as templates.js and chat.js)
    - `text.replace(/&/g,'&amp;').replace(/</g,'&lt;').replace(/>/g,'&gt;').replace(/"/g,'&quot;')`

**Form field toggling logic:**
- When `#sch-type` is 'once': show `#sch-once-fields`, hide `#sch-recurring-fields`
