## P0 — Ship today

### 1. `popup.html` static badge still says "YOLO"
- **Where:** `popup.html:22` — `<span id="modeBadge" class="mode-badge yolo">YOLO</span>`
- **Effect:** First paint shows "YOLO" before `chat.js`'s `updateApprovalModeUI` runs. The v3.5.0 changelog claimed this was renamed to "AUTONOMOUS (caution)". The actual UI flickers the dangerous old label every popup open.
- **Fix:** Change the static markup to `<span id="modeBadge" class="mode-badge approval">APPROVAL</span>` so the safe state is the default first paint. JS will downgrade to "AUTONOMOUS" only if the user explicitly opted out.

### 2. Stray test files in the release folder
- **Where:** `content/__sync_test.tmp`, `content/__bash_sync_test.tmp` — contain literal "test" / "synctest_…" strings
- **Effect:** They ship to the user's profile. Not loaded by the manifest, but they pollute the extension package and look unprofessional in a code review.
- **Fix:** Delete both files. Add `*.tmp` to your build/zip exclusion script.

### 3. README is two minor versions behind reality
- **Where:** `README.md:5` says version 3.2.0; `manifest.json:4` says 3.5.1. The "Sandboxed Execution" feature claim at `README.md:36` is also false — `EXECUTE_JS_SANDBOX_ENABLED = false` at `content/index.js:19`.
- **Effect:** Anyone evaluating the extension reads a security claim that isn't true. That's a credibility problem for an MSP product.
- **Fix:** Bump README badge, update the feature bullet to "Sandboxed execution (in development) — `execute_js` currently runs in MAIN world via CDP `Runtime.evaluate`; approval-mode gate enforces it when enabled." Keep the truth visible.

### 4. Goal URL auto-extractor matches inside ticket text and emails
- **Where:** `agent-engine.js:447-448` — first-iteration regex extracts URLs from `(?:go to|visit|navigate to|open) ...\.(?:com|org|...)`
- **Effect:** Paste a ticket like *"User cannot reach admin.microsoft.com after Outlook crashed; contact support@augustaitguys.com"* and the agent navigates to `https://admin.microsoft.com` unprompted — even though the goal was "summarize the ticket". The regex also matches your support email's domain (`augustaitguys.com`) as a navigation target.
- **Fix:** Two-part:
  - Tighten the trigger regex to require an explicit imperative *and* not appear in proximity to common email/issue-narration markers. e.g. require the URL phrase to be the **last 80 chars** of the goal, OR be preceded by "Begin at:" / "Start URL:" / "Go directly to".
  - Strip emails before regex: `goal.replace(/[\w.+-]+@[\w.-]+/g, '')` before URL detection.

### 5. No runtime password-field protection — system prompt is the only line of defense
- **Where:** Safety boundaries live entirely in the system prompt (`llm-client.js:545`). Content script `case 'type'` (`content/index.js:856`) does not check `input.type === 'password'` or autocomplete hints.
- **Effect:** A prompt-injection that bypasses the model's compliance, or a buggy plan, can type a literal password value into a `type=password` field. The README says "Sensitive fields (passwords, SSN, credit cards) are blocked at the content-script level" (`chat.js:135`) — they aren't.
- **Fix:** In `content/index.js` `case 'type'`, after `resolveCommandTarget`, hard-block when:
  - `el.type === 'password'`
  - `el.getAttribute('autocomplete')` matches `current-password|new-password`
  - `el.name`/`id` matches `/pass(word)?|ssn|cvv|card.?number|account.?number/i`
  - Return `'BLOCKED: type into password/sensitive field requires user keyboard entry'`. Same block in the CDP `cdpDispatchType` path in `tab-manager.js:256` if the prior `focus_element` reported the target was sensitive.

### 6. `extract` parser silently writes failure strings to memory
- **Where:** `agent-engine.js:1007-1018` — `JSON.parse(result.replace('JS Result: ', ''))`. If the extract returns plain text or an error string, parse fails and the action is marked failed; if the extract returns a quoted string like `"Element not found"`, `JSON.parse` succeeds and stores the failure as data.
- **Effect:** Hallucination vector — the finish summary may include "Element not found" as if it were extracted content.
- **Fix:** After the JSON.parse, validate: reject if `parsed.value` is `null`, an empty string, or matches `/^(Element not found|Error|JS Error|timed out|No element|Done)/i`. Mark `extractSucceeded = false` in those cases.

### 7. Auto-redirect from `chrome://` pages
- **Where:** `agent-engine.js:437-441` — any `chrome://`/`edge://`/`about:` page → auto-navigate to google.com.
- **Effect:** A technician on `chrome://settings/clearBrowserData`, `chrome://extensions`, `chrome://net-internals/#dns`, or `edge://policy` gets yanked to Google in the middle of a diagnostics task. For an IT-troubleshooting product this is the wrong default.
- **Fix:** Don't auto-navigate. Return `'Cannot operate on internal browser page. Switch to a normal tab or use a diagnostic action.'` and let the loop end gracefully. Keep the existing isValidUrl gate for *requested* navigations.

## P1 — Reliability core (this week)

### 8. Stale-ref fallback uses old selector against new DOM
- **Where:** `content/index.js:670-676` — when ref is stale, falls back to `cmd.selector` against the current document. The selector was generated at the previous scan; SPAs reorder `nth-of-type` chains constantly.
- **Effect:** Click lands on a different element than the LLM saw. Silent wrong-element interaction is worse than a clean failure.
- **Fix:** When ref is stale, do not silently fall back to a chain selector. Re-scan, then match by:
  1. `data-testid` / `aria-label` / `id` from the element's emitted record (ship those alongside the ref in the LLM observation),
  2. Visible text equality among elements of the same tag,
  3. Only then nth-of-type as a last resort.
  Return `'Element list rotated — re-observe before retrying'` if no high-confidence match is found.

### 9. `bbox` is viewport-relative but never refreshed against scroll
- **Where:** `dom-utils.js:218-225` emits `bbox` from `getBoundingClientRect()` (viewport CSS pixels, scroll-relative). The cached observation is sent to the LLM; if the page scrolls between the scan and the next click, the bbox is wrong.
- **Effect:** `click_at` lands on the wrong element after lazy-loaded content shifts the viewport.
- **Fix:** Two options:
  - (a) Emit page-absolute bboxes: `x: r.left + scrollX, y: r.top + scrollY` and pass `scrollX/scrollY` to the model in the prompt header.
  - (b) Force a re-scan if `command.type === 'click_at'` and the screenshot's `scrollY` differs from the live viewport's `scrollY` by more than 50px. Recommended: do (b) defensively even after (a).

### 10. Page observation runs every step regardless of staleness
- **Where:** `agent-engine.js:496-512` — `observe_page` + `read_page` on every loop iteration.
- **Effect:** A 50-step run does ~50 full DOM scans on the same page after micro-interactions. On a slow internal portal (NinjaOne, Datto Autotask) this is the dominant latency.
- **Fix:** Skip re-observation when (a) the previous step was a `note`/`extract`/`scroll` action that didn't change visible structure, AND (b) `isSPATransitionPending()` is false, AND (c) the current URL hasn't changed. Use the cached snapshot and decrement only `screenshotMeta.capturedAt`.

### 11. `dismiss_overlays` runs every step
- **Where:** `agent-engine.js:486-493` — call before every observation, capped at 3 dismissals total per page-load via `__sentinelDismissalCount`.
- **Effect:** After 3 dismissals, every subsequent call is a no-op that still costs a content-script round-trip. Worse, on long single-page sessions, `__sentinelDismissalCount` only resets on full document reload — but single-page apps don't reload, so by hour 2 of working a ConnectWise ticket the agent stops dismissing legit new modals.
- **Fix:** Track dismissal count per **URL+SPA-route**, not per content-script lifetime. Reset when `isSPATransitionPending()` clears or when `pathname+hash` changes.

### 12. `execute_js` sandbox claim vs. reality is a CYA mismatch
- **Where:** `EXECUTE_JS_SANDBOX_ENABLED = false` at `content/index.js:19`. The Proxy-based `createSandboxedDocument` / `createSandboxedWindow` exist but are dead code. Code now runs through CDP `Runtime.evaluate` (`tab-manager.js:304`).
- **Effect:** CDP runs in MAIN world with full page privileges and bypasses page CSP — fine for capability, but the security model is just "approval mode" + "model behaves". On a malicious page or via prompt injection, an LLM-emitted `execute_js` can read cookies, fetch with credentials, call internal APIs.
- **Fix:** Keep CDP for capability, but add a **static guard** before dispatch:
  - Reject `code` containing `document.cookie`, `window.localStorage`, `fetch(`, `XMLHttpRequest`, `WebSocket`, `eval(`, `Function(` unless approval mode is on AND the user explicitly approves *this* call. Show a clear "this code reads cookies / makes network calls" banner in the approval card.
  - Add a domain allowlist for sites where `execute_js` is OK without per-call approval (your own M365, ConnectWise, NinjaOne tenants), persisted in settings.

### 13. CDP attaches once per run but never reattaches if the user dismisses the banner
- **Where:** `tab-manager.js:106-117` — `chrome.debugger.onDetach` removes the tab from `attachedDebuggees` but never re-attaches.
- **Effect:** Technician dismisses the "Started debugging this browser" banner mid-task → next CDP call (`cdpDispatchClick`, `cdpExecuteJs`) silently fails → falls back to synthetic events → reCAPTCHA / Microsoft sign-in flows reject the events.
- **Fix:** In `ensureDebuggerAttached`, log when re-attach fires after a user-initiated detach and surface a chat warning: *"Debugger banner dismissed — re-attaching for trusted input. If you keep dismissing, click 'Disable trusted input' in settings to use synthetic events."*

### 14. Approval timeout is a silent reject after 60s
- **Where:** `agent-engine.js:1409-1412` — `setTimeout(... resolve({ rejected: true }), 60000)`.
- **Effect:** Better than the original auto-approve, but for an MSP technician on a phone call, 60s of inattention silently kills mid-task work. No user notification, no resumption hook.
- **Fix:** On timeout, **pause the agent** instead of rejecting. Send a `chrome.notifications.create` ping ("Sentinel paused — your approval is needed") and keep the request open. Only reject after a hard 5-minute outer wall.

### 15. No frame routing for OAuth / Stripe / SSO popups
- **Where:** `frame-router.js` and `index.js:107-122` — `execute_in_frame` exists, but there's no popup-window handler.
- **Effect:** Microsoft 365 / Google SSO open auth popups in **new windows**, not iframes. The agent loses the active tab and can't drive the auth flow. M365 admin work breaks here.
- **Fix:** Listen on `chrome.windows.onCreated` during a run. If a new window opens with an SSO-recognizable URL (`login.microsoftonline.com`, `accounts.google.com`, `auth0.com`, `login.okta.com`), promote it into the tracked tab map with label `"sso-popup"` and run a brief sub-loop to complete login, then return focus.

## P2 — MSP feature gaps that put you ahead of Claude in Chrome

### 16. No structured ticket-output mode
- **Where:** Nothing in `report-generator.js` or `chat.js` produces your team's required formats: TICKET KICKOFF / FINAL NOTES / WAITING ON CLIENT / WAITING ON VENDOR / IT GLUE KB / CLIENT EMAIL.
- **Effect:** You're hand-translating every agent output into your ticketing format. Claude in Chrome doesn't do this either — but it's the single highest-leverage MSP feature you could ship.
- **Fix:** Add a "Ticket Mode" toggle in the popup. When on:
  - First system-prompt section becomes: *"Produce output ONLY in one of these formats: TICKET_KICKOFF, FINAL_NOTES, WAITING_ON_CLIENT, WAITING_ON_VENDOR, IT_GLUE_KB, CLIENT_EMAIL. Choose based on the goal."*
  - Add an "Output Format" dropdown in the input area: Auto / Kickoff / Final / Waiting-Client / Waiting-Vendor / IT Glue / Email.
  - Auto-fill technician name (Brandon Goolsby), phone (706-426-6313), support email (support@augustaitguys.com) from settings.
  - The `finish` summary gets post-processed into the chosen template before being shown.

### 17. No `read_console_messages` / `read_network_requests` actions
- **Where:** Action list in `llm-client.js:667-694` lacks both. CDP exposes them via `Log.entryAdded` and `Network.requestWillBeSent` / `Network.responseReceived`.
- **Effect:** Claude in Chrome has these. They're how you diagnose AJAX failures, OAuth callback loops, broken CORS, certificate errors — *exactly* the bugs MSP techs chase. Without them, the agent is blind to client-side errors a technician would see immediately in DevTools.
- **Fix:** Two new actions wired through CDP:
  - `read_console_messages` — last 50 entries from `Log.entryAdded` (level, text, url, lineNumber, timestamp).
  - `read_network_requests` — last 30 requests with method/url/status/duration; optional `filter` param for `4xx|5xx|failed`.
  - Attach the listeners on first use and buffer in the background. Persist across the run.

### 18. No native diagnostics action surface
- **Where:** Tasks like "ping 8.8.8.8 from this machine" or "run nslookup admin.microsoft.com" — none of these exist as actions. The user's MSP profile literally lists ping/nslookup/Test-NetConnection/Event Viewer as expected tools.
- **Effect:** The agent can drive a remote-tools web UI (Premier Networx Remote, Splashtop, ScreenConnect Command tab) but has no first-class diagnostic primitives.
- **Fix:** Two complementary moves:
  - Add a `run_remote_command` action that drives the ScreenConnect Command tab (or NinjaOne Run Action). Platform context already covers the UI; standardize the action with `{type, machine_label, command_type: 'powershell|cmd|bash', command: '...'}`.
  - For tasks the agent can do without the remote machine (DNS lookups, public IP info), add a `lookup` action that resolves via public DNS over HTTPS (1.1.1.1) — purely informational, no network privileges escalation.

### 19. No "import a ticket" workflow
- **Where:** `popup.html` input is a freeform textarea; `templates.js` is for *pre-saved* templates.
- **Effect:** Pasting a ConnectWise ticket means manually editing it into a goal. The user's preference doc literally says "Paste a ticket description (include ticket number, client, issue, and prior attempts)" — that's a structured input, not a goal.
- **Fix:** Add a "Paste Ticket" panel: structured fields for ticket #, client, issue, prior attempts, target system, success criteria. The agent assembles the goal in your preferred TICKET_KICKOFF format. Save the parsed ticket as a runbook automatically when finished.

### 20. Platform context is hardcoded text — no per-platform selectors
- **Where:** `llm-client.js:16-222` — every platform gets a paragraph of guidance. No DOM selectors, no test-id hints, no per-vendor `wait_for_text` strings.
- **Effect:** The model has to discover SonicWall's "Add Rule" button selector every time. NinjaOne's device search input is in the same DOM position 99% of the time but the agent re-scans.
- **Fix:** Promote each platform to a structured profile:
  ```js
  // background/platforms/sonicwall.js
  export const sonicWall = {
    detect: (url, goal) => /.../,
    knownSelectors: {
      loginUsername: 'input[name="userName"]',
      addRuleButton: 'button[title="Add"]',
      ...
    },
    waitStrings: { dashboardReady: 'Welcome' },
    commitFlow: ['Accept', 'Apply', 'OK'],
    sessionExpiredText: 'Session has expired',
  };
  ```
  Inject `knownSelectors` as hints in the prompt. When a known selector is in the live DOM, the LLM should prefer it.

### 21. No verification step after a configuration change
- **Where:** Plan generator at `llm-client.js:304-327` mentions verification, but the agent doesn't enforce it. Final summary often says "rule was created" without re-reading the rules table.
- **Effect:** False-positive completions on firewall/RMM tasks. That's a ticket reopener.
- **Fix:** When the goal is detected as configuration (`/create|add|delete|modify|update|enable|disable|block|allow/i` + a network-device platform context), inject a mandatory final step: `read_page` + `extract` confirming the configured value is present. Refuse `finish` until that extract returns a non-empty match.

### 22. Self-learning patterns leak client info to local storage
- **Where:** `agent-engine.js:1346` — `goal.substring(0, 100)` saved to `learned_patterns`. Goals routinely contain client names, IPs, ticket numbers.
- **Effect:** `chrome.storage.local` is per-profile, persistent across uninstalls (sometimes), and synced if Chrome sync is on. PII/PCI considerations.
- **Fix:** Scrub before save:
  - IPs → `XXX.XXX.XXX.XXX`
  - Emails → `[email]`
  - Ticket-number patterns (`/\b(?:TKT|TICKET|#)\d+/i`) → `[ticket]`
  - Common client-name capture: anything between quotes → `[client]`
  - Add a settings toggle "Disable pattern learning" for users who prefer no persistence.

### 23. Agent memory is global, not per-task
- **Where:** `agent-engine.js:17` — `agentMemory = {}` is module-scope; `resetAgentState()` wipes it but `runAgentLoop` *restores* `agent_memory` from storage at line 323.
- **Effect:** Memory from yesterday's "list M365 users at Acme" leaks into today's "check firewall logs at Beta Co". Cross-client data contamination.
- **Fix:** Namespace memory under a per-run UUID. Persist final memory only into the run's report (not into a global key). Restoration at session start should require an explicit "Resume previous run" choice.

### 24. No audit trail for what was clicked / typed
- **Where:** `history` array is in memory, capped at 40 entries; only the last 20 are persisted; final report includes them but it's a free-form summary.
- **Effect:** When something goes wrong on a client environment, you need a *forensic-grade* log of every click, typed value, and URL. Currently the agent's report can't be relied on for that — it's narrative.
- **Fix:** Write a structured `agent_run_log` entry per step into a separate storage key with tabId, URL, action, target ref/selector, result, timestamp, screenshotHash. Ship a "Export run log" button to download as JSON or CSV. This is a Real MSP Differentiator.

## P3 — Polish / repo hygiene

### 25. Folder name vs. version drift
- **Where:** Folder is `sentinel-override-v3.4.0` but `manifest.json:4` is `3.5.1`.
- **Fix:** Rename the working folder when bumping version, or drop the version from the folder name and rely on tags / `manifest.version`.

### 26. ID generation: `requestApproval` falls back to `Math.random`
- **Where:** `agent-engine.js:1385-1387`.
- **Effect:** No security risk in extension context, but `crypto.randomUUID()` is available in service workers since Chrome 92 — fallback is dead code on any supported version.
- **Fix:** Drop the fallback or move to `crypto.getRandomValues` if you want belt-and-suspenders.

### 27. `popup-state.js` is 83 lines — lightweight, but no actual reactivity for tab/agent state
- **Where:** `popup-modules/popup-state.js`. Tab state arrives via `sendTabStateUpdate` and re-renders the whole list on every change.
- **Effect:** Minor. Multi-tab UI flickers when many tabs update at once.
- **Fix:** Diff renders by `tabId`. Only redraw rows that changed. Optional, but makes the agent feel snappier on multi-tab tasks.

### 28. `provider-registry.js` lists the model presets in code but settings UI doesn't surface them in a picker
- **Where:** `popup-modules/settings.js`.
- **Effect:** Users type endpoints by hand; presets in the README aren't selectable. New techs onboarding to your MSP have to copy/paste 4 fields.
- **Fix:** Render the registry as a dropdown in settings: pick "Anthropic Claude Sonnet 4.6" → endpoint + model autofill, prompt for API key only.

## What this puts you ahead of Claude in Chrome on

After P0-P2 ship, the differentiators that actually matter for an MSP:

1. **Ticket-format-aware output.** Claude in Chrome produces a chat answer; you produce a TICKET KICKOFF / FINAL NOTES / IT GLUE KB block.
2. **Forensic run log** (item 24). Every click and typed value, exportable.
3. **Per-platform selector profiles** (item 20). SonicWall / FortiGate / ConnectWise / NinjaOne / Datto / IT Glue with known DOM hints — the model doesn't have to discover the same UI twice.
4. **Console + network observability** (item 17). You're diagnosing client-side bugs; the agent should see them too.
5. **SSO popup handling** (item 15). M365 admin work without the agent losing the auth window.
6. **Verification-required configuration changes** (item 21). Closes the false-positive completion gap that bites every browser agent on firewall work.
